- [ ] 3.1 Add `accounts: Arc<RwLock<HashMap<String, Arc<AccountSession>>>>` to `ServerState`, with a method to get-or-create an `AccountSession` for a given `account_key` (constructing a fresh `InnerTube` on first sight of that key, restoring its cookie from the `accounts` table if a `StoredAccount` row already exists for it), and verify a unit test exercises concurrent get-or-create calls for the same key returning the same `Arc`.
- [ ] 3.2 Update `RequireSession::from_request_parts` to resolve session id → `account_key` (unchanged) → look up the matching `AccountSession` from the new map (removing the old single `state.app.it.is_logged_in()` global check), rejecting as unauthenticated when the account_key has no live session, and change it to hand back the resolved `Arc<AccountSession>` (not just the bare `account_key` string) so handlers don't each re-look it up. - [ ] 3.3 Update every route handler currently taking `_session: RequireSession` (library.rs, playlists.rs, ratings.rs, settings.rs, lastfm.rs, auth.rs's gated routes, media.rs's `register_play`, ws.rs's `upgrade`) to use the resolved `AccountSession` (its `it` for InnerTube calls, its `account_key` for DB calls) instead of `state.app.it`/an unscoped DB call, and verify `cargo build -p server` succeeds with no remaining direct reads of a single global `InnerTube` or unscoped per-account settings/plays call.
- [ ] 3.4 Leave `browse.rs`, `search.rs`, and `blocked.rs` as anonymous/ungated exactly as they are today (per design.md: anonymous metadata lookups and the deliberately-ungated `blocked_artists` setting, respectively) — verify no `RequireSession` was added to any of their routes.
